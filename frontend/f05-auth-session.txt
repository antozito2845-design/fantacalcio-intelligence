F05 — AUTHENTICATION & SESSION UX
Date: 2026-08-22

- HTTP Basic credentials are held only in React state memory.
- No localStorage, sessionStorage, URL, frontend environment or file persistence.
- Login validation uses read-only GET /squads: 200 valid, 401 invalid.
- Admin capability uses read-only GET /admin/catalog/readiness: 200 admin; 403 after successful user probe means authenticated non-admin.
- Login page supports labels, password field, visibility toggle, loading and differentiated credentials/access/network messaging.
- PublicOnlyRoute, ProtectedRoute and AdminRoute provide UX guards while the backend remains authoritative.
- Global 401 invalidates credentials and clears query state.
- Manual logout and expected session loss after refresh verified.
- Browser smoke verified real user login, logout, real admin login/capability and refresh loss. Invalid credentials returned 401 in the live probe and render the dedicated message in the UI integration test.
